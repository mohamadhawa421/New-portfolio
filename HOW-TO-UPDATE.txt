===============================================================================
 HOW TO UPDATE YOUR PORTFOLIO
 Add or edit projects, then put the changes live.
===============================================================================

You need two things open: the Terminal app, and your browser.
Everything below is copy-and-paste. Nothing here can break the live site
until the very last step.


-------------------------------------------------------------------------------
 EVERY TIME — START HERE
-------------------------------------------------------------------------------

Open Terminal and paste this, then press Enter:

    cd ~/code/mohamad-hawa-portfolio

That points the Terminal at your project. You must do this first, every
time you open a new Terminal window.

TIP: instead of typing the path, type "cd " (with the space), then drag the
project folder from Finder onto the Terminal window and press Enter.


-------------------------------------------------------------------------------
 STEP 1 — OPEN THE ADMIN
-------------------------------------------------------------------------------

    npm run edit

Wait until it stops printing. Then open this in your browser:

    http://localhost:1337/admin

Log in with the account you created. (First time on a new computer it will
ask you to create one — that account is only on that computer.)

Leave the Terminal window alone while you work. It is running the admin.


-------------------------------------------------------------------------------
 STEP 2 — ADD OR EDIT A PROJECT
-------------------------------------------------------------------------------

In the left sidebar: Content Manager > Project

To edit:  click the project you want to change.
To add:   click "Create new entry" (top right).

Fill in the fields. The ones that matter most:

  Title          The project name, e.g. "Kanz".
  Slug           The web address. Click "Regenerate" and it fills itself in
                 from the title. Leave it alone after that — changing it
                 later breaks any link anyone has already shared.
  Categories     One row per service the project belongs to. Add a row and
                 type the service name, spelled exactly:
                     Landing page / showcase website
                     Mobile app
                     Web app
                     Design system
                     Redesign web / mobile
                 A project can have more than one — a redesign that shipped
                 as a web app has both, and it then shows up under either
                 filter. Put the main one first: it leads the label on the
                 card. These are the filter buttons on the Work page, and a
                 service with no projects under it is left out of them, so a
                 typo makes a button with one project in it.
  Discipline     Free text, shown on the case study, e.g. "Web app design".
  Summary        One line. Appears on the card and under the title.
  Order          0 is first. Lower numbers come first. To put a new project
                 at the top, give it 0 and add 1 to the others.
  Featured       Tick this for the ONE project that gets the big treatment
                 at the top of the home page. Untick it on the old one
                 first — two featured projects means the first one wins.

  Cover          The card image.
  Approach shot  The screen shown beside "The approach".
  Gallery        The screens under "What shipped".

  Brief lead / Brief body        The opening of the case study.
  Problem lead                   One line naming the problem.
  Constraints                    The numbered list. Put the whole sentence
                                 in "Title" and leave "Body" empty — that is
                                 how the existing ones are set up.
  Approach lead / Approach body  What you did. Line breaks are kept, so
                                 bullet lists are fine.
  Decisions                      The three "Outcome" cards.
  Metrics                        The three highlights at the bottom.
                                 "Value" is the short name, "Label" is the
                                 sentence under it.
  Reflection lead / body         The "Looking back" section.

Leave a field empty and that part of the page simply does not appear.

*** THE STEP EVERYONE FORGETS ***

    Click the "Publish" button (top right) on every entry you touched.
    A saved-but-unpublished entry is invisible to the website.


-------------------------------------------------------------------------------
 STEP 3 — STOP THE ADMIN
-------------------------------------------------------------------------------

Click on the Terminal window and press:  Control + C

(Hold Control, press C. Not Command.) This stops the admin. You have to do
this before the next step, because the next step needs the database to
itself.


-------------------------------------------------------------------------------
 STEP 4 — PUT IT LIVE
-------------------------------------------------------------------------------

    npm run deploy

That is the whole thing. It will print four steps:

    [1/4] Reading the CMS database
    [2/4] Building the site to check nothing is broken
    [3/4] Committing
    [4/4] Pushing to main

Then "Done." Your live site updates about a minute later:

    https://mohamadhawa.vercel.app

To label the change (optional but nice):

    npm run deploy -- "Added the Acme project"

If it says "Nothing changed", you probably forgot to hit Publish in step 2.

If it stops with an error, NOTHING was pushed and your live site is
untouched. Read the message — it usually names the problem. Most common is
an image referenced by a project that is missing from the media library.


-------------------------------------------------------------------------------
 WANT TO SEE IT BEFORE IT GOES LIVE?
-------------------------------------------------------------------------------

Instead of step 4:

    npm run refresh

Then open http://localhost:4321 in your browser. That is the real site,
running on your computer only. When you are happy, press Control + C to
stop it and run "npm run deploy".


-------------------------------------------------------------------------------
 IF SOMETHING GOES WRONG
-------------------------------------------------------------------------------

"command not found: npm"
    You opened a new Terminal and did not run the "cd" line at the top.
    Run it and try again. If it still says that, run:
        echo 'export PATH="/opt/homebrew/opt/node@22/bin:$PATH"' >> ~/.zshrc
    then close the Terminal and open a new one.

"Missing script: deploy"
    You are in the wrong folder. Run "pwd" — it should end in
    "mohamad-hawa-portfolio". If not, run the "cd" line at the top.

Port 1337 already in use
    The admin is already running in another Terminal window. Find it and
    press Control + C, or just close that window.

The live site did not change
    Two usual causes: you did not hit Publish, or "npm run deploy" ended
    with an error. Scroll up in the Terminal and read what it said.

I published something by mistake
    Nothing is lost. Vercel keeps every previous version. Go to
    vercel.com, open the project, click "Deployments", find the one from
    before your change, and use the "..." menu to promote it back to
    production.


-------------------------------------------------------------------------------
 THE ONE THING TO REMEMBER
-------------------------------------------------------------------------------

Editing in the admin changes nothing on its own. The website is built from
an export of the database, and only "npm run deploy" makes that export.

    Edit  ->  Publish  ->  Control + C  ->  npm run deploy
